# 运营工作台只放日常工作

日期：2026-10-19  
状态：待实现  
载体：微信小程序管理端 `pages/admin/home`、`pages/admin/catalog`、`pages/admin/inbox`  
范围：调整入口位置。订阅规则、入队规则、关于页内容和云函数保持现状。

## 1. 要解决什么

运营登录后的工作台把日常工作、通知开关、一次性维护和版本说明做成同一种卡片。页面文案还写着「以后增加模块会放在这一页」，新能力就继续往这一屏贴。

工作台的用途是挑一件会反复做的工作进去。通知、重处理和版本少占注意力，并跟到它们所属的工作里。

## 2. 以后怎么加

工作台只放会反复进出的工作。现在是三行：内容运营、商品运营、客服工单。

- 一块新的重复性工作，才在工作台增加一行。订单履约做成可进入的工作时，与这三行并列。本设计不实现订单页。
- 开关、额度和一次性修复，放进它服务的那块工作。
- 版本和环境留在工作台底部一行，不另做卡片，也不再集中到「更多」。

## 3. 工作台

删掉开头的「选择要处理的工作。以后增加模块会放在这一页。」

自上而下：

1. **内容运营**。副文案仍是「品牌、讲解视频的入库与上架」。点这一行进入 `/pages/admin/catalog/catalog`。
2. **商品运营**。保持现有标题、副文案和进入商品运营的行为。本设计不改商品页。
3. **客服工单**。副文案仍是「回复用户问题并关闭已处理工单」。点这一行进入 `/pages/admin/inbox/inbox`。右侧仍是待处理数量：有则「N 条待处理」，无则「暂无待处理」。`csAdminList` 失败时右侧为「工单加载失败」，并 toast 现有失败文案。

底部一行小字，文案为现有环境标签加包内版本，例如「开发版 · 0.2.3」。它不是工作卡片。点击进入 `/pages/about/about?staff=1`。

工作台不再放置「接收新工单通知」「重处理不合格视频」「版本与日志」三张卡片，也不再调用 `csNotifyConfig`、`csRegisterNotify`、`csUnregisterNotify`。

内容运营右侧与转码进度共用第 5 节的文案。页面显示时读一次 `getIngestProgress`，不在工作台轮询。

票据无效时仍 `redirectTo` 登录页。这条规则适用于本设计涉及的全部管理端读取。

## 4. 内容运营

主操作仍是「添加品牌」和品牌列表。品牌区域之后增加一行「重处理不合格视频」。品牌加载中、品牌列表为空时，这一行仍然可见。

点这一行进入现有 `/pages/admin/ingest/ingest`。右侧文案与工作台「内容运营」行相同，页面显示时读一次进度，不在本页轮询。

重处理页本身不变：确认文案、`enqueueNoncompliantVideos`、进度列表，以及有排队或正在转时每 8 秒轮询，都留在该页。

## 5. 转码入口文案

工作台的内容运营行、内容运营页的重处理行，使用同一个纯函数。放在 `miniprogram/utils/ingestEntryLabel.js`，两页不要各写一套优先级。

函数形如 `ingestEntryLabel({ running, queued, failed, failedToLoad })`。缺省和非数字按 0。输出：

1. `failedToLoad` 为真，或三个数都不是正数：`进入`。读取失败时不用上一次的数字。
2. `running > 0`：`正在转`
3. 否则 `queued > 0`：`N 条排队`
4. 否则 `failed > 0`：`N 条失败`

请求尚未返回时按全零处理，显示「进入」。不显示「暂无排队」或「查看进度」。

## 6. 客服工单

状态筛选上面增加通知区。工单列表、筛选、回复和关闭不变。

通知区沿用现有交互，只改所在页面：

- 标题「接收新工单通知」。说明「每次允许只能收一条。停止后不再推送。」
- 页面显示时调用 `csNotifyConfig`。右侧按现有顺序：无模板 ID 为「未配置」；未开启为「未开启」；`quota > 0` 为「还可接收 N 条」；其余为「额度已用完」。
- 点击通知区：无模板 ID 时 toast「未配置通知模板」，不调用 `wx.requestSubscribeMessage`。有模板 ID 时请求订阅。回调里该模板为 `accept` 才调用 `csRegisterNotify`，并用返回的 `enabled`、`quota` 刷新，toast「已开启，还可接收 N 条」。`reject`、`ban`、`filter` 或调用失败不登记、不改额度，toast「未允许，这个微信收不到通知」。
- `enabled === true` 且模板已配置时，区内显示「停止接收」。该按钮不触发订阅。成功调用 `csUnregisterNotify` 后显示「未开启」。停止失败保留原状态，toast「停止失败」。
- 每个微信各自开关。搬移入口不改变 `admin_notify_subscribers` 的字段和发送规则。

`notifyLabelText` 随通知区从 `home.js` 移到 `inbox.js`，继续导出给测试。通知配置读取失败时不改当前右侧文案，页面初始文案是「未开启」；这不改变工单列表，列表自己的失败提示保持现状。

通知的数据、额度和发送仍以 `docs/superpowers/specs/2026-10-16-admin-notify-subscription-design.md` 为准。该规格把入口放在工作台；入口位置以本文为准。

## 7. 不改什么

- 不新增订单入口，不新建「更多」页。
- 不改云函数、订阅额度、入队条件和关于页正文。
- 不改「我的」里的关于入口。用户路径仍不带 `staff=1`。
- 不改重处理页的确认、入队和轮询。
- 不引入新的视觉体系。工作入口继续用现有 `hub-item`；底部版本用现有次要文字样式。

## 9. 验收

1. 打开工作台，只看到内容运营、商品运营、客服工单，以及底部的环境与版本。没有通知卡、重处理卡、版本卡，也没有「以后增加模块会放在这一页」。
2. 没有转码排队、正在转或失败时，内容运营右侧是「进入」。有失败且没有更优先的状态时，右侧是失败条数；点这一行仍进入内容运营。
3. 内容运营页在没有品牌时仍能进入重处理，重处理页的确认和入队与现在一致。
4. 在客服工单页允许、拒绝和停止通知，结果与现在在工作台操作相同。工作台不再弹出订阅窗。
5. 底部版本行进入的更新说明仍包含内部条目。从「我的」进入的关于页仍不包含内部条目。
