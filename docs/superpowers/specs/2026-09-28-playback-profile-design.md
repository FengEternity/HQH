# 讲解视频播放规格与入库预处理

日期：2026-09-28  
载体：`scripts/video-ingest` 与 `catalog` 云函数（分支 `dev-playback-normalize`，从 `dev-video-ops-ingest` 迁出）  
范围：统一小程序可流畅播放的编码规格；本批已上架片子按该规格重编码并替换云存储文件；以后运营上传必须先过同一套预处理才能上架。

不改 `main` 上的播放页，不改 `getVideo` 换临时链，不重新发小程序包。

## 背景与决策

体验版播放的是现在 `main` 上的全屏 `<video>`，地址来自云函数换成的 HTTPS 临时链。播放页从 0.1.0 起没有改过，播放过程中也不会反复 `setData`。卡顿来自片源：本批 23 条里，21 条是 H.264 原片直接拷贝，关键帧间隔 10 秒；「南方面测量」「南方数据导出」由 HEVC 转成 H.264 后仍是 60 帧、High profile、带 B 帧。开发者工具和本地播放器看这些文件是顺的，真机体验版会卡。

现有预处理模块已经在 `scripts/video-ingest`：批量走 `preprocess.js`，运营上传后走 `worker.js`。两边只在「不是 H.264 或有音轨但不是 AAC」时转码，所以长关键帧间隔和 60 帧会被放过。

对话中已确认：

- 扩展现有入库模块，不另写一套预处理程序。
- 本批 23 条全部重编码，上传新文件，只替换已有记录的 `videoFileId`，保持上架。
- 后续运营上传也走同一规格：未处理完不能上架。
- 播放页保持不动。

## 目标

- 一份播放规格纯函数，批量预处理和 worker 共用。
- 不符合规格的文件必须转码；转码产物再次检查，仍不合格则失败，不得上传。
- 本批 23 条替换云存储中的播放文件，已上架状态、简介、字幕、封面不变。
- 运营之后上传的视频，在 worker 按该规格处理完成之前不能上架。

## 非目标

- 改播放页布局、临时链或小程序包
- 云函数内跑 ffmpeg
- 重编码封面、重跑转写、改简介
- 把视频发给第三方
- 多开 worker，或给任务续租

## 播放规格

合格条件（全部满足才算合格）：

| 项 | 要求 |
| --- | --- |
| 视频编码 | H.264 |
| Profile | Main 或 Baseline |
| 像素格式 | yuv420p |
| 宽度 | ≤ 1280，高度为偶数 |
| 帧率 | ≤ 30 |
| B 帧 | 无 |
| 关键帧间隔 | 最大间隔 ≤ 2 秒 |
| 容器 | moov 在 mdat 之前 |
| 音频 | 无音轨，或 AAC |

转码参数：

- `libx264`，`-profile:v main`，`-pix_fmt yuv420p`，`-preset medium`，`-crf 23`，`-bf 0`
- 宽度超过 1280 时缩到 1280，高度取偶数；不放大
- 源帧率高于 30 时降到 30，否则保持源帧率
- 关闭场景切换额外关键帧，最大关键帧间隔 2 秒
- `-movflags +faststart`
- 有音轨时 AAC、128 kbps；无音轨时不补音轨

纯函数根据 ffprobe 结果返回是否合格以及原因列表。需要转码的判断只调用它，不再手写「codec 是否为 h264」。

## 模块

规格与 ffmpeg 参数放在 `scripts/video-ingest/lib/playbackProfile.js`。

- `preprocess.js` 用它决定 `transcodeRequired`，并使用同一组 ffmpeg 参数。
- `worker.js` 用它决定是否转码，转码后再次检查。不合格则以处理失败回写，不上传产物，不替换 `videoFileId`。
- 转码成功后把检查结果写入记录的 `media.playback`（编码、profile、像素格式、宽高、帧率、是否有 B 帧、最大关键帧间隔、是否 faststart、音频编码）。这个对象只由 worker 完成回写和下面的替换脚本写入。运营保存表单不提交、也不覆盖它。

本批 23 条按该检查都不合格，因此会全部重编码。以后已经合格的文件直接拷贝，避免每次入库再压一遍。

## 本批替换已上架文件

新脚本 `scripts/video-ingest/replace-playback.js`。默认只打印计划；`--execute` 才上传并写库。凭据用本机已有的云开发环境变量，不写入仓库，不出现在命令行参数里。

对 manifest 里每一条：

1. 检查本地重编码文件。不合格则这一条失败，不上传。
2. 用标题精确匹配云端 `videos` 记录。零条或多条都算失败，不猜测。
3. 上传新 mp4。
4. 更新该记录的 `videoFileId` 和 `media.playback`，并把处理状态写成完成、回写文件 ID 写成这个新文件。不改上架状态、简介、字幕、封面，不重新排队，不触发新的转写。这样以后重新上架仍能通过门禁。
5. 写库成功后再删除旧的云存储文件。写库失败则删除刚上传的新文件，保留旧文件。

一条失败不回滚已经成功的其它条。结束时列出成功、失败和未匹配的标题。库里若有这 23 条以外的已上架视频，只列出来，不修改。

已上架的片子不会因为缺少 `media.playback` 被自动下架。

## 后续运营上传

运营在管理页上传视频并保存后，行为保持现有入库队列：

1. 原文件先进入云存储，记录进入排队，此时不能上架。
2. 本机只运行一个 `worker.js`。它下载原文件，按播放规格检查，需要时转码，再检查产物。
3. 合格后上传到 `video/processed/`，回写新的 `videoFileId`、`media.playback`，处理状态为完成。
4. 运营核对标题、封面、简介后再上架。
5. 原始文件在回写成功后删除。失败则保留，管理页继续显示「处理失败」和原因，可重试。

worker 未启动时，记录停在排队，上架按钮不可用。不在云函数里转码。

## 上架门禁

`assertReadyToPublish` 在现有「封面和视频已有、处理中不能上架、简介不能是占位句」之外，再要求：

- 处理状态正好是完成，排队、处理中、失败都不能上架
- `videoFileId` 等于这次处理回写的文件
- `media.playback` 满足上面的合格条件

运营换了一份新原片时，沿用现有换片行为：清掉旧的播放检查结果并重新排队。不能带着上一份合格结果把新原片直接上架。

## 错误处理

- 转码或二次检查失败：该条标记失败，不上传，不改已有 `videoFileId`
- 替换时标题匹配不是恰好一条：跳过该条
- 替换写库失败：删新文件，留旧文件
- 删除旧文件失败：记录已指向新文件，日志里留下旧 `fileID`，不把整批打成失败
- 不在失败时改上架状态

## 测试

- 播放规格：10 秒关键帧、60 帧、High profile、B 帧、HEVC、非 AAC 音轨判为不合格；Main、30 帧、无 B 帧、2 秒关键帧、faststart、AAC 判为合格
- ffmpeg 参数包含 Main、无 B 帧、2 秒关键帧、faststart，并且与 worker、预处理是同一组参数
- 预处理：现有 H.264 + AAC 但关键帧间隔 10 秒的片子 `transcodeRequired === true`
- 上架门禁：完成且 `media.playback` 合格才能上架；排队、失败、缺少播放检查、文件 ID 与回写不一致都不能上架
- 替换计划：标题唯一才生成写库步骤；多条或零条不生成上传

本批文件转码后用 ffprobe 复核规格。替换脚本先干跑。`--execute` 依赖本机云开发凭据，凭据缺失时停止，不上传。体验版是否还卡，用真机看替换后的片子确认。

## 分支

实现留在 `dev-playback-normalize`。合入 `dev` 并部署更新后的 `catalog` 之后，运营上传的门禁才会在体验版生效。只跑替换脚本就能换掉这 23 条正在播的文件，不必先发小程序。
