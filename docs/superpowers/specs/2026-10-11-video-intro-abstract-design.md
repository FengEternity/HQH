# 转写后生成功能简介

状态：讨论稿。写法以 `scripts/video-ingest/intro-abstract.examples.json` 的三则简介为准，术语表以 `scripts/video-ingest/terms.zh-CN.json` 的现稿为准。实现仍在 `dev-video-ingest-intro`，不在 `main` 上直接改。

对照：`docs/superpowers/specs/2026-10-08-cloud-transcode-design.md`（同一云托管、先转码再转写）、`docs/superpowers/specs/2026-09-15-ops-upload-auto-ingest-design.md`（`introSource`、占位句、人工稿不覆盖）。

**产品：** 转写成功后，自动写一段给 C 端看的简介。写法跟这三则认可稿同一类：先点明品牌和功能，再按口播里的真实顺序写下主要操作，去掉片头、片尾和过细的单次点击。用术语表改正听错的词。不上架前仍由运营核对。不把某一句旧宣传语逐字复现，也不补这期标题和口播都没出现的格式或连接方式。

## 1. 简介长什么样

认可稿在 `scripts/video-ingest/intro-abstract.examples.json`。三则分别是千寻数据导入、千寻线测量、华测手簿无线升级。数据导入那则的认可简介是：

> 本期视频讲解千寻仪器的数据导入功能：手簿连接电脑后，将数据复制到 C7 内部存储的导入文件夹，再在手簿数据界面选择 CSV 格式导入控制点文件，最后通过点库查看导入详情。适合需要学习数据导入操作的用户。

整段 40～160 字。句数不设上限，5 句、6 句只要还在这个字数里就留下。模型要改的是错字和废话，保留这期实际走过的路径。例如把「千询一气」写成「千寻仪器」、把「手部」写成「手簿」，去掉「大家好」和「点赞并转发」。

不合格：

- 把口播逐句接起来
- 保留「大家好」「点赞」「下期再见」
- 补上这期标题和口播都没出现的型号、文件格式或有线/无线/一键

## 2. 放在哪一步

仍是云托管服务 `video-ingest`，最大实例 1，容器内同时只处理一条任务。顺序不变：可播转码、转写、再写简介。转写用现有 CPU 版 faster-whisper `small`。简介在转写进程退出之后，用容器内的 llama.cpp 跑 Qwen3-4B-Instruct 的 Q4_K_M（GGUF，约 2.5GB）。关掉该模型的思考输出，只要正文。

口播、标题、品牌名不出容器，不调用外部文本接口。权重在构建镜像时拉进镜像，构建参数沿用 `HF_HUB_DISABLE_XET=1`，运行中的任务不再为模型访问外网。权重文件不进 git。

现有「至少 2GB」装不下转写模型加这个摘要模型。云托管的 CPU 与内存按 1:2 搭配，没有 2 核 8GB 这一档：2 核只配 4GB，4 核才配 8GB。Q4_K_M 权重大约 2.5GB，短口播推理时连同计算缓存大约要 3～4GB，2 核 4GB 会在加载时被系统杀掉。发布带摘要的版本时，该服务改为 **4 核 8GB**。转写结束并释放之后再加载摘要模型，两套权重不要同时常驻。多出来的核数用于 CPU 推理，最大实例数仍是 1，没有任务时最小实例数仍是 0。

摘要单独限时 3 分钟。超时、模型起不来或验收不通过：字幕照常回写，`asr=ready`，简介保持占位，不把整单打成失败。无音轨、转写失败时不跑摘要，行为与现在相同。

`introSource=human` 时不覆盖简介，字幕仍可更新。`placeholder` 和 `auto` 在重新处理时可以改写简介。

不改叫醒和进度页。领取结果额外带回该条的 `title` 和 `brandName`，抢锁方式不变。`catalog` 的完成回写已经接受非空 `intro` 并标 `introSource=auto`，完成接口不必再做逐步取证。

## 3. 一次模型调用

输入只有四样：

| 材料 | 来源 |
| --- | --- |
| 标题 | 这条 `videos.title` |
| 品牌名 | 这条已选中的 `brandName`，只传这一个品牌 |
| 术语表 | 仓库里的正确写法列表，见 §4 |
| 口播 | 本次 `transcriptSegments` 拼成的原文 |

模型在同一次回复里做两件事：按术语表把明显听错的词改成正确写法，再写成 §1 的简介。术语表里有、但这期口播没说到的词，不能写进去。

库里的 `transcript` / `transcriptSegments` 保存识别原文，不回写改正后的口播。搜索仍能靠 `brandName` 命中品牌；错字留在字幕里，给运营核对。

不再用 `resolveAutoIntro` 的逐句拼接作为 C 端简介。本地批量导入原来的逐步取证可以留在本地审核，不接到这条云托管路径上。

## 4. 术语表

文件就是现稿 `scripts/video-ingest/terms.zh-CN.json`，先不删减，随镜像进容器。`terms` 是正确写法，含行业词、应用名、格式词和连接词；`brandNames` 是品牌正式名。表里不登记错字。模型不负责扩充这张表。

提示里带上整份 `terms`，外加本片 `brandName`。`brandNames` 不整表塞进提示，只给验收用来拦住别的品牌。术语表里的格式词、有线、无线、一键，不能因为进了表就写进这期简介；仍要这期标题或口播里出现过。

## 5. 验收

模型返回后用规则决定是否入库。规则不负责写简介，只拒绝越界的事实。普通动词可以是改写，不要求在口播里原样出现。

整段不入库、简介保持占位，若出现任一情况：

- 空、短于 40 字、长于 160 字，或按「。」「！」「？」切开后没有一句
- 含「大家好」「点赞」「下期再见」或现有占位句
- 不含本片 `brandName`
- 出现术语表以外的、且不是本片 `brandName` 的其他品牌正式名（术语表提供全库品牌名时才做这项）
- 出现文件格式词（如 csv、dat、txt、xls、dxf），但标题和口播原文里都没有这个词
- 出现「有线」「无线」「一键」「蓝牙」，但标题和口播原文里都没有
- 出现术语表中的词，但标题、品牌名、口播原文里都没有这个词，口播里也没有与之同音的一段。同音用完整的无声调拼音，繁体和多音字都算，认不出的字各自占位、不会互相配上。允许中间多一个音节，以便放过「千询的仪器」这类夹字。字母和数字不参与比对

通过则回写 `intro`，`introSource=auto`。编辑页沿用现有文案：占位时是「字幕已出，简介需手写」，自动简介写上后是「待核对后上架」。

不自动填 `searchAbstract`、`entities`、`tags`、`modelName`。不自动上架。

## 6. 不做什么

- 不把口播或成片发给容器外的模型
- 不用规则模板从口播里抽取简介
- 不要求简介复现某一句既有宣传语
- 不按产品卡片补口播没说的格式和连接方式
- 不改 mentor 正在热修的领取、叫醒和进度页
- 不在生产再开一套本机 worker 与云托管并行

## 7. 验收标准

单测不加载真实模型，也不连接云。

- 用三则对照构造提示时，提示里含该条品牌名、`terms` 和原文，不含逐步拼接的旧简介
- 验收函数接受 `intro-abstract.examples.json` 里的三则 `intro`
- 验收函数拒绝在数据导入那条口播上写出 dat、txt、无线、一键、点赞，或短到只剩品牌加标题的文本
- 摘要超时或验收失败时，完成回写仍带 `asr=ready` 和字幕，不带 `intro`
- `introSource=human` 时完成回写即使带了 `intro` 也不覆盖
- 仓库内没有权重文件。镜像构建只预拉转写模型；摘要 GGUF 在容器启动后下载，避免 7GB 级镜像推送失败

上线后用试验片点「重新处理」：字幕仍是识别原文，简介接近数据导入那则认可稿，编辑页为「待核对后上架」。运营改过简介后再处理，简介不变。

## 8. 还要补的材料

术语表和三则对照已经落在上面两个文件里。云托管规格确认为 4 核 8GB。约 2.5GB 的 Qwen3-4B-Instruct Q4_K_M 在容器启动后下载，不打进镜像。运行时口播不出容器。
