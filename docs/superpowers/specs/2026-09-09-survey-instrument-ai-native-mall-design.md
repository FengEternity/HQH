# 仪器讲解资料馆：商城与 AI Native 能力（产品需求）

日期：2026-09-09  
载体：现有微信小程序 + 微信云开发（本仓库）  
对外名称：仪器讲解资料馆  
运营主体：优度（杭州）智能装备有限公司

## 背景与决策

一期已经能做品牌/视频目录、关键词搜索、播放、运营入库、首页客服留言。没有可购商品、没有支付订单，也没有统一的检索服务。

本期要在同一小程序里补上两件事：讲解之后能买；围绕已入库内容做 AI 搜索、播放页文档问答和 AI 客服。实现路径定为继续云开发，商城与 AI 以新云函数接入，不新开用户端、不新开独立 Web 后台。

对话运行时：播放页问答与客服 tab 的 AI **共用 `@earendil-works/pi-agent-core` 作为 harness 内核**（Agent 循环、工具调用、状态与事件流），模型访问走 `@earendil-works/pi-ai`。业务差异只体现在 system prompt、工具集和会话作用域，不另写一套生成循环。不接入 `pi-coding-agent` 的文件系统 / shell 类工具。

主路径：用户先找讲解、看完，需要时再进商城下单支付。商城是讲解的出口。首页默认仍是讲解 tab。

## 成功标准（第一期同时满足）

1. 讲解 tab 可浏览、播放；顶栏 AI 搜索默认返回已上架视频。
2. 商城 tab 可走完：列表/搜索 → 详情（含关联讲解）→ 购物车 → 微信支付 → 「我的」订单（待付款 / 已付款 / 已关闭）。
3. 播放页展示关联上架商品；商品详情展示关联已上架视频。关联为多对多，由运营手工维护。播放页视频下方有文档问答对话框：问当前这条讲解，不跳转客服 tab。
4. 客服 tab 默认 AI（全站讲解/商品/本人订单）；常驻「转人工」；转人工后生成工单，运营可在小程序回复，运营与用户均可收到订阅消息（授权失败则只靠打开对应页，工单不丢）。
5. 播放页问答与客服 AI 均由同一套 pi-agent-core 会话接口驱动；检索通过 agent 工具调用统一 `search`，不在小程序里直连模型。
6. 下单收集收货人姓名、手机、地址，供线外履约使用。小程序不展示运单、不维护发货物流状态。

## 信息架构

底栏四项，从左到右：**讲解｜商城｜客服｜我的**。启动默认讲解。

| 入口 | 职责 |
| --- | --- |
| 讲解 | 现有资料馆（品牌、列表、空态）。顶栏搜索 `scene=video`。点条目进播放页。 |
| 商城 | 商品列表（可按分类或全部）、顶栏搜索 `scene=product`、详情、购物车、确认订单。 |
| 客服 | 同一条对话时间线。默认每句走 AI。常驻「转人工」。转人工后仍留在本页看工单，不跳转微信原生客服会话。 |
| 我的 | 本人订单列表与详情、收货信息管理、待付款重新支付或取消。不展示物流轨迹。 |

非底栏跳转：

- 播放页：上方播放器，中部关联商品（点进商品详情），**下方 AI 文档对话框**（见「播放页文档问答」）。不提供「去客服问」、不自动跳转客服 tab。
- 商品详情 → 关联视频播放页；加购 / 立即购买。
- 客服消息中的视频 / 商品卡片 → 播放页或商品详情。
- 运营入口保持现网：`pages/admin/login/login` 或首页品牌行连点 8 次。不进底栏。

用户要人工客服时，自己切到底栏「客服」并点转人工。播放页对话框不提供转人工。

一期现有独立页 `pages/contact/contact` 并入客服 tab（或客服 tab 直接复用该页并改交互），用户不再需要从讲解页标题进一套并行客服。

## 商城

### 商品（可售 SKU）

现网云集合 `products` 表示品牌下的**型号**（`name` + `brandId`），视频上的 `productId` 指向它。商城可售货必须用新集合 **`shop_products`**，禁止把型号记录直接当成可支付 SKU。

`shop_products` 至少包含：名称、价格（整数，单位分）、主图 fileId、详情文案、规格（第一期最多一个规格维度，例如套装/成色；无规格则单一 SKU）、上架状态 `published | unpublished`、可选分类名、创建/更新时间。未上架不得出现在 C 端列表、搜索、播放页「相关商品」。

上架条件：名称、价格（≥0 的分）、主图。不做库存数量、仓位、运费模板。是否可卖以是否上架为准。不在系统内拦截超卖。

### 视频与可售商品关联

新集合 **`video_shop_links`**：`videoId`、`shopProductId`，唯一约束二者组合。一条视频可挂多个 `shop_products`；一个 `shop_product` 可被多条视频引用。运营在视频编辑或商品编辑里勾选对方。

播放页只列出关联且 `published` 的商品。商品页只列出关联且已上架的视频。型号（`products`）继续用于讲解筛选与搜索字段，不作为购买关联的唯一键。

### 购物车、结算、支付

登录身份：微信云开发 `openid`。每用户一份购物车（集合 `carts`：openid、sku 行列表 `shopProductId`、数量、规格值）。

结算页提交：勾选行、数量、收货人姓名、手机、地址、可选备注。服务端按当前上架价重算金额，**不信任前端应付额**。生成订单 `status=pending_pay`，拉起微信支付。

订单状态只允许：

- `pending_pay` 待付款
- `paid` 已付款（支付回调验签通过后写入）
- `closed` 已关闭（用户取消或超时未付）

禁止第一期出现「已发货 / 运输中 / 已签收」。已付款订单供运营在后台只读列表里做线外发货。

退款：第一期不在系统内自动退；用户走客服工单，运营在微信支付商户平台处理。订单状态不因退款自动变化（若必须记录，另开一期加 `refunded`，本期不做）。

支付取消：订单保持 `pending_pay`，可重新支付。关闭后不可再付。

### 「我的」订单

仅本人：商品快照（名称、规格、单价分、数量、主图）、应付额、状态、收货信息、下单时间、微信支付单号（如有）。无物流字段。

## 统一 AI 搜索服务

独立云函数 **`search`**（名称可在实现计划里微调，但必须与 `catalog`、商城分开入口）。讲解搜索框、商城搜索框、以及 agent 工具「找片/找货」都调用它。禁止为这些入口复制多套检索逻辑。

### 请求

- `scene`：`video` 或 `product`（第一期只这两个）
- `query`：用户原句
- `limit` / `offset`：分页

### 处理

1. 清洗与理解：去空白、可调用模型做纠错与检索词扩展；品牌/型号归一复用集合 `synonyms`。
2. 检索：只扫 C 端可见数据。视频侧字段：标题、简介、标签、`modelName`、`brandName`。商品侧字段：名称、详情文案、规格、分类。索引单位为「片段」；第一期一条视频简介或一条商品详情文案视为一个片段。视频上若已有 `searchAbstract` / `transcript` / `transcriptSegments`（现网字段），有内容则一并检索，**运营不强制先做转写才能上架**。
3. 场景派生：`video` 主列表为视频，可附带最多 3 条由 `video_shop_links` 得到的上架商品。`product` 主列表为 `shop_products`，可附带最多 3 条关联已上架视频。不做全局混排、不做意图路由到单一类型。
4. 响应：统一条目 `{ type: 'video' | 'shop_product', id, title, coverFileId, summary, score, related?: [] }`。前端负责卡片样式。

### 降级与空结果

- 模型理解超时或失败：降级为现有 `catalog` 关键词检索（视频）或 `shop_products` 字段关键词（商品），界面注明「已用关键词结果」。
- 命中 0 条：提示换词，并提示可到另一 tab 再搜（讲解无结果可去商城，反之亦然）。
- 检索基础设施失败：返回明确错误，不得伪装成空库。

C 端不得命中草稿视频、下架商品、未发布关联。

第一期不做：向量库（接口可留空字段，实现不加依赖）、用搜索框闲聊、按播放进度自动切章节问答、生成讲解片。播放器可把当前播放秒数作为可选上下文字段传给文档问答 agent，模型不据此强制seek。

## Agent harness（pi-agent-core）

云函数 **`agent`**（Node）内嵌 `@earendil-works/pi-agent-core` 的 `Agent` 循环：收用户消息、按工具定义调用、流式或整包返回 assistant 事件。模型由 `@earendil-works/pi-ai` 配置，密钥只放云函数环境变量。

同一内核、两种 profile（实现上是两套 `system` + `tools`，不是两个 npm 包）：

| profile | 入口 | 会话键 | 工具 |
| --- | --- | --- | --- |
| `video_doc` | 播放页下方对话框 | `openid + videoId` | 仅检索**当前视频**文档字段（标题、简介、标签、型号/品牌、已有 `searchAbstract`/`transcript*`）及该视频 `video_shop_links` 上的上架商品；可返回商品卡片。无订单工具、无转人工工具。 |
| `cs` | 客服 tab | `openid`（全局客服线程） | `search`（`video` / `product`）、查本人订单、转人工（写工单并停模型）。 |

小程序不跑 agent 循环，只渲染消息与卡片，并把用户输入、`profile`、会话键交给 `agent`。云函数超时：单轮工具调用次数设上限（建议 ≤5）；超时返回可理解错误，会话状态仍落库，可重试。禁止把编码 agent 的 read/write/bash 接到本产品。

## 播放页文档问答

布局从上到下：播放器 → 标题/简介/标签 → 关联商品 → **对话区**（历史 + 输入框）。对话区文案按「针对本条讲解提问」，不是全站客服。

- 只回答当前 `videoId` 对应文档与关联可售商品；问到其它型号/其它视频时说明请回讲解搜索或打开对应播放页，可给搜索建议，但不把会话扩成全站客服。
- 出处卡片可点关联商品；不跳客服 tab。
- 未登录允许只读提问（实现可用匿名 openid）；一旦涉及下单引导，只出商品卡，支付仍走商城。
- 会话与客服 tab **不合并**。同一用户在 A 视频下的问答不会出现在 B 视频或客服工单里，除非后续单独做「带引用转发」，本期不做。

## 客服

客服 tab 一条线程（集合 `cs_threads`：用户 openid、状态见下、更新时间）。消息集合 `cs_messages`：threadId、role（`user | assistant | operator | system`）、文本、可选卡片（video / shop_product / order）、时间。

线程状态与后台列表对应：`ai` 仅 C 端 AI 中（不进待处理队列）；`waiting_human` = 待处理；运营发出第一条回复后改为 `human` = 处理中；运营关闭 = `closed`。

现网 `support_messages` 在实现时迁移或双写后切到工单模型，C 端只呈现一套对话。快捷问题（现 `miniprogram/config.js` 的 `contact`）可保留为输入建议，点选后当作用户消息走 AI，不再只做本地死回复（「领取账号」类运营配置回复可以仍走规则，须在实现计划里列白名单）。

### AI 默认行为

客服走 `agent` 的 `cs` profile。每条用户消息：内容安全检查（与现网一致；本地可 `SKIP_CONTENT_CHECK`，正式环境不可）→ pi-agent-core 循环（工具内调 `search`、查订单）→ 生成回答。须遵守：

- 只根据检索到的上架内容与用户本人订单回答；没有依据则说明不知道，并提示转人工或去讲解/商城搜索。
- 能引用则带卡片，禁止只给无法跳转的纯链接文案。
- 已登录可查本人订单状态（待付款/已付款/已关闭），禁止编造物流或发货时间。
- 不代替下单与支付。

模型超时：提示重试，转人工按钮仍可用。播放页 `video_doc` 超时同样可重试，仍不出现转人工。

### 转人工

按钮常驻。点击后：

1. 线程进入 `waiting_human`。
2. 写入系统消息：已转交运营。
3. 之后用户消息只追加到工单，**不再进入 pi-agent-core 循环**，直到运营关闭工单且用户开启新线程（关闭后下一句用户消息开新 `ai` 线程，旧线程只读）。
4. 向**已在运营端订阅「新工单」模板**的账号发订阅消息。运营 openid 在首次成功登录工作台时写入集合 `admin_notify_subscribers`（可多条）。未订阅则跳过发送，工单仍为待处理。

### 运营回复与用户通知

运营在小程序后台工单列表处理：待处理优先，可回复、可关闭。回复写入 `operator` 消息，用户在客服 tab 可见，并向用户发订阅消息「客服已回复」（用户未授权则不发，消息仍在线程里）。

第一期不做：多客服抢单、质检、跳转微信原生客服。

订阅消息模板在实现时于微信公众平台申请两条：`CS_NEW_TICKET`（运营）、`CS_REPLIED`（用户）。未配置模板时，转人工与回复的数据路径仍必须成功。

## 运营后台

仍用 `ADMIN_PIN` 票据。工作台增加：

- **商品**：`shop_products` CRUD、上架/下架、与视频多对多关联。
- **订单**：按状态筛选；已付款用于履约；待付款/已关闭只读。不填写运单、不改物流状态。
- **客服工单**：待处理 / 处理中 / 已关闭；查看转人工前的 AI 上下文；回复；关闭。

品牌与视频编辑规则保持现网（上架需封面、视频、简介等）。品牌改名仍同步视频上的 `brandName` 与搜索索引。

## 云函数与数据

| 模块 | 职责 |
| --- | --- |
| `catalog` | 品牌、型号 `products`、视频、同义词、initDb 中与目录相关的集合。不处理支付。 |
| `shop` | `shop_products`、购物车、订单、微信支付统一下单与回调、收货地址。 |
| `search` | 统一检索。供搜索框与 agent 工具调用。 |
| `agent` | pi-agent-core 运行时：`video_doc` / `cs` 两套 profile、会话读写、工具调度。 |
| `cs` | 转人工、运营回复、订阅消息、工单列表。可与 `agent` 同仓不同 action，但转人工不得绕过工单状态机。 |

集合增量：`shop_products`、`video_shop_links`、`carts`、`orders`、`user_addresses`、`cs_threads`、`cs_messages`、`video_doc_threads`、`video_doc_messages`（按 `openid+videoId`）、`admin_notify_subscribers`。Agent 会话消息与 C 端展示共用上述 message 集合，不另存一份「模型私有 log」作为用户可见历史。`initDb` 幂等创建。权限：仅管理端/云函数可读写，C 端一律经云函数。

密钥、`ADMIN_PIN`、支付商户密钥不得进入 git。

## 错误处理（跨模块）

- 未登录访问购物车/下单/订单/客服写操作：要求微信登录后重试。播放页 `video_doc` 允许未登录提问。
- `agent` 未知 `profile` 或 `video_doc` 缺少 `videoId`：拒绝请求。
- 商品在结算瞬间已下架：拒绝下单并说明。
- 支付回调乱序/重复：按微信支付单号幂等，已是 `paid` 则忽略。
- 内容安全未通过：不入库用户文本，返回可理解错误。

## 验收与测试

产品手测：

- 草稿视频、下架商品不出现在讲解搜索、商城搜索、关联位、客服卡片。
- 讲解搜索命中上架视频；商城搜索命中上架商品；两框都走 `search`（可用日志或返回头里的 `scene` 证明）。
- 支付一笔沙箱/测试款后，「我的」为已付款；取消支付保持待付款。
- 播放页与商品页互链只含上架对象；播放页下方可对当前视频提问，不跳客服；问到无关视频时不扩成全站客服。
- 客服能根据检索结果回答并出卡片；转人工后运营收到通知（若已授权）并回复，用户能看到回复。
- 空库：讲解/商城有空态，不报错。

自动化（不依赖真机微信的部分）：

- 订单状态机：仅允许 `pending_pay → paid | closed`，金额以服务端价格计算。
- `search`：`scene=video` 不把下架商品当主结果；`scene=product` 不把草稿视频当主结果。
- 转人工后同一线程不再进入 pi-agent-core 循环（可用伪 Agent 断言）。
- `video_doc` 工具不得对非当前 `videoId` 做全库 `scene=video` 检索（可用固定夹具断言）。

## 非目标（第一期）

仓储物流与运单、库存扣减、自动退款状态机、优惠券、评价、直播、推荐流、独立 Web 运营后台、全局单一混合搜索框、强制语音转写才能检索、AI 生成讲解视频、播放进度内问答、多商户。

## 后续（同一架构上的下一刀，不在本期验收）

- 字幕/口播转写写入已有 `transcript*` 字段并进入 `search` 片段。
- 向量检索作为 `search` 内可切换实现。
- 订单履约状态（已发货）若运营需要再单独立项。
- 流量或超时迫使 `agent` / `search` 从云函数拆到云托管时，保持 profile 与 `search` 的 `scene` 协议不变。

## 对实现计划的拆分建议

本文件是一份产品总 spec。落地时应拆成可独立验收的计划，例如：底栏与讲解/商城壳页 → `shop_products` 与关联 → 购物车支付订单 → `search` 与两处搜索框 → 云函数接入 pi-agent-core 与播放页 `video_doc` → 客服 `cs` profile 与转人工通知 → 运营商品/订单/工单。不要按一份计划一次改完所有云函数。

实现只在 **`dev`**（或从 `dev` 拉出的短分支）上进行；**`main` 仅发布验证**。见 `docs/branching.md`。
