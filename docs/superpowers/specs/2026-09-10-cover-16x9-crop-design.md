# 首页封面 16:9 裁剪与展示

日期：2026-09-10  
载体：现有微信小程序（`miniprogram/`）  
范围：运营编辑页选图 / 视频首帧进入同一裁剪页；首页与运营预览共用 16:9 卡片。不改云存储权限，不改封面换链逻辑。

## 背景与决策

首页卡片封面容器约 2:1（宽约 344rpx、高 176rpx），运营编辑预览约 2.14:1。相册图和视频缩略图多为 16:9（约 1.78:1）。两端 `<image>` 都用 `aspectFill`，会铺满后裁掉上下。运营端看到的裁切范围还不完全等于首页，所以封面标题看起来像被截断。

对话中已确认：

- 统一比例：**16:9**。
- 裁剪方式：进入独立页，**可拖动、双指缩放后确认**。
- 无手动封面、使用视频首帧时，**同样进入该裁剪页**，不自动居中落库。
- 不保留原图再云端动态裁；确认后导出固定尺寸 JPEG 再上传。

## 目标

运营选封面或视频自动带出首帧时，能在 16:9 取景框里移动、缩放并确认。确认后的文件与首页卡片同一比例。首页卡片高度改为 16:9，新封面不再因容器比例额外裁切。

## 非目标

- 云端按焦点动态裁图、多比例衍生图
- 给 C 端用户提供裁剪
- 批量重裁已上架封面
- 改存储 ACL、换链、`getTempFileURL`
- 封面滤镜、贴纸、文字叠图

## 约定

| 项 | 值 |
| --- | --- |
| 比例 | 16:9（宽:高） |
| 导出 | JPEG，`1280×720`，质量约 0.8 |
| 缩放 | 最小为「短边铺满取景框」（不能露出空白）；最大为最小缩放的 4 倍 |
| 拖动 | 图片始终盖住取景框；越界回弹到最近合法位置 |
| 过小 | 原图任一边小于 640px 时 toast 提示可能发糊，仍允许确认 |
| 取消 | 返回编辑页，不改已有 `coverFileId` / 预览 |
| 旧数据 | 已上传封面继续展示；`aspectFill` 作兜底。点「更换封面」才重裁 |

## 页面与数据流

新增页面：`pages/admin/cover-crop/cover-crop`（仅运营路径，不进 tabBar）。

几何与导出计算放在纯函数模块 `miniprogram/utils/coverCrop.js`（可单测），页面只负责手势、canvas 导出、回传路径。

```text
选相册图 / 拿到视频 thumbTempFilePath
        │
        ▼
navigateTo cover-crop（eventChannel 传本地临时路径）
        │
        ├─ 取消 / 返回 → 不上传、不覆盖
        └─ 确认 → canvas 导出 1280×720 JPEG 临时文件
                    │
                    ▼
              编辑页 uploadCloudFile('cover', ...)
              写入 coverFileId，预览用本地裁剪结果
```

编辑页改动：

- `pickCoverPhoto`：`chooseMedia` 成功后先打开裁剪页，确认后再 `ensureSaved` + 上传。
- `uploadVideo`：`plan.action === 'upload_thumb'` 时，先裁剪 `thumbTempFilePath`，再上传封面；`keep` / `missing_thumb` 行为不变。
- 预览框改为 16:9（`width: 100%; padding-top: 56.25%` 或等价写法），文案写明「将按首页卡片 16:9 裁剪」。

首页改动：

- `.cover` 由固定 `height: 176rpx` 改为 16:9（相对卡片内容宽度）。
- `.cover-img` 仍 `mode="aspectFill"`，作为旧图或比例误差的兜底。
- 运营视频列表缩略图改为同一 16:9，避免后台看起来又被切一刀。

不把裁剪结果写进数据库新字段；仍只存一个 `coverFileId`。

## 裁剪页交互

- 深色背景；中央固定 16:9 取景框，框外半透明遮罩。
- 框内图片可单指拖动、双指缩放；提供「重置」回到最小缩放且居中。
- 底栏：取消、确认。确认时 `wx.showLoading`，导出失败 toast，不关闭页、不上传。
- 取景框内不叠品牌角标，避免运营按角标对齐；首页角标仍由卡片 CSS 叠加。

导出：用离屏或隐藏 canvas，按当前位移/缩放把可见 16:9 区域画到 1280×720，再 `canvasToTempFilePath`。不把原图整张上传后再让服务端裁。

## 错误与边界

- 用户取消选图、取消裁剪、裁剪页返回：编辑页状态与打开裁剪前一致。
- 导出或上传失败：保留裁剪页或回到编辑页原封面，toast 说明失败。
- 视频无 `thumbTempFilePath`：仍提示手动选封面（现有 `missing_thumb`）。
- 横图、竖图、已是 16:9：同一套最小缩放规则，竖图默认显示中段，运营可自己拖。

## 测试

`coverCrop.js`（`node --test`）：

- 给定图片尺寸与取景框，计算 `minScale`、初始居中位移。
- 缩放低于最小值、拖出取景框时被夹紧。
- 确认时源矩形映射到 `1280×720`（整数像素，不越出原图）。

编辑页流程：`planVideoCoverUpload` 的动作名不变（`keep` / `upload_thumb` / `missing_thumb`）。`upload_thumb` 时页面先打开裁剪页，确认后再上传裁剪结果；单元测试不必为「插入裁剪」改动作名。

## 手测

1. 横屏 16:9 封面图：裁剪页几乎铺满，确认后首页文字完整。
2. 竖图：默认中段，上移后顶部标题进入框内，首页与预览一致。
3. 只传视频不选手动封面：进入裁剪页，取消则不写封面。
4. 已有封面点更换后取消：仍显示旧封面。
5. 旧封面未重传：首页仍能显示（可能仍被 `aspectFill` 切一点）。

## 影响面

- 改：`app.json` 注册裁剪页；`edit.js` / `edit.wxml`；`app.wxss` 首页 `.cover`、`.cover-frame` 与运营列表缩略图。
- 增：`pages/admin/cover-crop/*`、`miniprogram/utils/coverCrop.js` 及测试。
- 不改：catalog 云函数换链、播放页海报逻辑（仍读 `posterUrl`）。
