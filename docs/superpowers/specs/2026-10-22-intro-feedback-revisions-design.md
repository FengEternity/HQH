# 简介回前台、离开页面后刷新、简介版本

状态：已确认。实现在 `dev-intro-feedback`，从 `dev` 迁出，不在 `main` 上改。

对照：`docs/superpowers/specs/2026-10-11-video-intro-abstract-design.md`（`acceptIntro` 闸门）、`docs/superpowers/specs/2026-09-15-ops-upload-auto-ingest-design.md`（占位句、`autoIntro` / `humanIntro`）。

**产品：** 模型写出的简介，闸门过不过，都回到运营编辑页，并标明要核对。保存之后才能上架。处理太久还没有正文时，编辑页和列表允许先手写。运营离开编辑页后，视频列表自己刷新处理状态。每条视频留下自动稿和人工稿的版本，供以后做数据集。闸门规则不放宽。

## 1. 生成结果一律留下

`acceptIntro` 仍按现有规则判断。不因为「四参数」这类词未在口播里出现就改规则。

整理后的正文如果是空的，或就是占位句「讲解处理中，完成后请核对简介。」，当作没有生成结果：不改 `intro`，不改 `autoIntro`，不写 `introGate`，不追加版本。

有非空正文时，Worker 在中途回写（`noteVideoIntro`）和完成回写（`completeVideoIngest`）都带上：

| 字段 | 含义 |
| --- | --- |
| `intro` | 整理后的正文 |
| `introGate.ok` | 闸门是否通过 |
| `introGate.reason` | 未通过时的原因原文，例如 `term 四参数`；通过时为空字符串 |

服务端：

- `autoIntro` 写成这段正文。
- 视频文档上的 `introGate` 写成这次的结果。
- 按 §4 追加一条 `kind=ai` 的版本。
- 没有手写简介，且视频不是已上架：`intro` 写成这段正文，搜索跟着这段文字。
- 已有手写简介，或视频已上架：`intro` 保持不动。已上架视频的对外简介和搜索仍是运营确认过的那一版。
- 没有手写简介时，`introReview` 设为 `pending`。已有手写简介时，`introReview` 保持 `confirmed`。

手写简介以库里的 `humanIntro` 经去掉占位句后是否非空为准。

## 2. 运营确认

`introReview` 只有 `pending` 和 `confirmed`。

运营在编辑页点「保存」，且保存后的对外简介不是占位句：`introReview` 设为 `confirmed`。不改字、原样保存自动稿，也算确认。此时 `humanIntro` 仍为空，`intro` 与 `autoIntro` 相同。

上架闸门在现有条件之外增加一条：`introReview` 必须是 `confirmed`。未通过时的提示是「上架前请先核对简介并保存」。小程序 `miniprogram/utils/videoPublishGate.js` 和云函数 `cloudfunctions/catalog/lib/videoPublishGate.js` 两处一起改。

旧数据没有 `introReview`：对外简介非空且不是占位句时，视为 `confirmed`，避免已有视频无法上架。否则视为 `pending`。

## 3. 编辑页提示

编辑页继续在处理中每 5 秒拉取这条视频。提示按下面的顺序，命中一条就用它：

1. 已有自动稿，且 `introReview` 为 `pending`：
   - 闸门通过：「自动简介已填入，请核对。保存后才能上架。」
   - 闸门未通过：「自动简介已填入，但未通过检查（原因）。请核对修改，保存后才能上架。」
   - 处理仍在排队或进行：「播放文件仍在处理」接在上一句后面。
2. 没有自动稿，也没有手写简介，阶段是排队或进行，且从 `ingest.queuedAt`（没有或为 0 则用 `startedAt`）起已超过本节的等待时间：「处理时间较长，可先手写简介。自动稿出来后留在对照里，不会盖掉你写的。」两个时间都没有或都是 0 时，不显示这句。
3. 阶段已是完成或失败，没有自动稿，也没有手写简介：「没有生成简介，请手写后再保存上架。」
4. 其余沿用现有阶段提示。

等待时间只影响这句提示，不把任务标成失败。按片长计算：

```text
等待 = min(30分钟, max(15分钟, 8分钟 + 视频时长 × 2))
等待 = min(等待, 45分钟)
```

视频时长用 `durationSec`。没有、为 0 或不是有限正数时，等待时间是 15 分钟。最短 15 分钟，按片长最多放到 30 分钟，从入队起最多 45 分钟。相册或电脑文件夹选到的时长随这次上传写入 `durationSec`；聊天记录没有时长时先按 15 分钟。处理完成后的探测时长仍覆盖这份上传时长。

闸门原因按前缀换成这句「原因」，认不出的前缀显示「未通过检查」：

| `introGate.reason` 前缀 | 显示 |
| --- | --- |
| `term ` | 后面的词 + 「未在口播里出现」 |
| `length ` | 字数不合要求 |
| `sentences ` | 不成句 |
| `banned ` | 含有不应出现的套话 |
| `placeholder` | 仍是占位句 |
| `brand` | 未写明本片品牌 |
| `other-brand ` | 写了别的品牌 |
| `format ` | 出现了口播里没有的格式 |
| `capability ` | 出现了口播里没有的连接方式 |

已有手写简介，且自动稿和手写不同：保留现有「用这次结果替换」。闸门未通过时，同一行加上「未通过检查（原因）」，原因用上一张表。

## 4. 离开编辑页后列表自己刷新

视频列表在页面显示时拉取。只要当前列表里还有 `ingest.phase` 为 `queued` 或 `running` 的条目，就每 8 秒再拉一次。没有这类条目，或页面隐藏、卸载时，停止计时。

小程序退到微信后台后，定时器会停。回到列表或编辑页时再刷新。

列表状态字：

| 条件 | 状态字 |
| --- | --- |
| 排队或进行，已超过 §3 的等待时间，且没有自动稿也没有手写简介 | 可先手写 |
| 排队 | 排队 |
| 进行中 | 正在转 |
| 失败 | 失败 |
| 完成，且 `introReview` 为 `pending` | 待确认 |
| 完成，转写跳过 | 无音轨 |
| 完成，其余 | 待核对 |

「可先手写」优先于「排队」和「正在转」。等待时间与 §3 相同，两个时间都没有或都是 0 时不使用这句。列表要能读到 `durationSec`。

## 5. 简介版本

视频文档增加 `introRevisions`，只追加。最多 50 条，超出时丢掉最旧的。版本号只增不减：新条目的 `version` 是当前数组里最大 `version` 加 1；数组空时从 1 开始。丢掉旧条目不回收版本号。

每条：

| 字段 | 含义 |
| --- | --- |
| `version` | 整数 |
| `kind` | `ai` 或 `human` |
| `text` | 正文 |
| `gateOk` | 自动稿为布尔；人工稿为 `null` |
| `gateReason` | 自动稿的原因原文；人工稿为空字符串 |
| `createdAt` | 毫秒时间戳 |

追加规则：

- 自动稿：最新一条 `kind=ai` 的正文与这次相同，则不追加。`introGate` 仍更新为这次的结果。
- 人工稿：运营保存时，若对外简介不是占位句，且与最新一条版本的正文不同，追加 `kind=human`。与最新一条正文相同则不追加。
- 原样保存自动稿时，最新一条就是这条自动稿，正文相同，不再追加。原样采用看视频字段：`introReview` 为 `confirmed`，`humanIntro` 为空，`intro` 与 `autoIntro` 相同。
- 运营改写后的正文与最新一条不同，追加 `human`。数据集里，一条 `ai` 之后第一条正文不同的 `human`，就是这次改写。

这次不做出导出页面，也不给标题做版本。

## 6. 不做什么

- 不放宽 `acceptIntro`
- 不把已上架视频的对外 `intro` 换成尚未保存的自动稿
- 不在小程序进入微信后台后继续轮询
- 不因超过等待时间把任务标失败
- 不做版本导出
- 不记录标题版本

## 7. 验收标准

单测不加载模型，也不连接云。

- 闸门拒绝且正文非空时，完成回写仍写入 `autoIntro`、`introGate.ok=false` 和原因，并追加一条 `ai` 版本
- 闸门拒绝且正文是占位句或空串时，不改 `intro` / `autoIntro`，不追加版本
- 未上架且没有手写简介时，对外 `intro` 变成自动稿，`introReview` 为 `pending`
- 已上架或已有手写简介时，对外 `intro` 不变；已有手写简介时 `introReview` 仍为 `confirmed`
- 中途回写与完成回写送入同一段自动稿时，只留一条 `ai` 版本
- 运营保存非占位简介后，`introReview` 为 `confirmed`；正文与最新版本不同时追加 `human` 版本；正文相同时不追加
- 没有 `introReview` 的旧文档，简介不是占位句时仍可上架；`pending` 时两处上架闸门都拒绝
- 编辑页在有自动稿且待确认时使用 §3 的核对文案；超过 §3 的等待时间仍无正文时使用手写提示；处理结束仍无正文时使用「没有生成简介」
- 没有时长时等待 15 分钟；3 分钟片等待 15 分钟；8 分钟片等待 24 分钟；20 分钟片等待 30 分钟；任何片长都不超过 45 分钟
- 列表在存在排队或进行中的条目时每 8 秒刷新，离开页面后停止；待确认显示「待确认」，超过等待时间且无正文显示「可先手写」
- `introRevisions` 超过 50 条时只保留最新 50 条，新版本号仍比被丢掉的最大版本号大
