# 运营人员名单

日期：2026-10-22  
状态：已实现
载体：云函数 `catalog`、`shop`、`ticketing`，小程序「我的」、工作台、初始化页、邀请领取页、人员页  
范围：用微信身份区分管理员和运营。两边都能做现有日常工作。只有管理员能管理人员。普通用户看不到运营入口。

## 1. 要解决什么

现在所有运营共用环境变量 `ADMIN_PIN`。登录票据不绑定某个微信，不能单独停用一个人。首页标题连点 8 次会打开口令页，普通用户可能点进去。

管理员和运营做同一套内容、商品和工单。管理员额外管理人员名单。

## 2. 身份

调用云函数时以微信上下文里的 OpenID 为准。客户端传来的 OpenID 无效。

集合 `admin_users`，一个 OpenID 一条记录：

| 字段 | 含义 |
| --- | --- |
| `openid` | 这个微信 |
| `role` | `admin` 或 `operator` |
| `enabled` | 停用后为 false |
| `createdAt` | 加入时间 |
| `updatedAt` | 最近一次角色或启用状态变化 |

昵称不存在这里。人员页和领取结果读取现有 `cs_profiles`。没有昵称时显示「未设置昵称」。页面不展示 OpenID。

`initDb` 幂等创建 `admin_users` 和 `admin_invites`。权限仍是仅管理端可读写，小程序只通过云函数访问。

## 3. 谁能操作

三个云函数里现有的管理接口不再接受「只凭票据」。每次都查当前 OpenID：

- 没有记录、已停用或 OpenID 为空：`UNAUTHORIZED`。
- 记录启用：可以做现在的内容、商品和工单操作。
- 人员接口还要求 `role === 'admin'`。运营调用时返回 `FORBIDDEN`，工作台不因此退出。

停用立即生效，下一次云函数调用就被拒绝。微信端不另发票据，也不再把 `hqh_admin_ticket` 当作入口依据。

不能停用或降级自己。启用中的管理员至少保留一名：这次修改会让启用的管理员变成零人时，拒绝。

## 4. 第一个管理员

还没有启用中的管理员时，初始化页可以输入 `ADMIN_PIN`。口令正确就把当前微信写成启用的管理员，并进入工作台。口令错误提示「口令不正确」。

已经有启用中的管理员时，初始化页不再接受口令，文案是「初始化已完成」，并回到「我的」。这时即使口令正确也不新增管理员。

两个微信同时提交时，后写入的一方在写入前再查一次。已经有管理员就拒绝。这个窗口只存在于还没有管理员的时候。

`ADMIN_PIN` 继续只放在云函数环境变量里，不进仓库。三个云函数仍配置同一个值。

批量视频导入和云端转码通过 CloudBase 服务端 SDK 调用 `catalog`，没有微信 OpenID。为保持现有流程：

- `adminLogin` 在微信上下文有 OpenID 时，只执行本节的首名管理员绑定，不返回票据。
- `adminLogin` 在微信上下文没有 OpenID 时，继续用 `ADMIN_PIN` 返回 12 小时服务票据。
- 服务票据只在 OpenID 为空时有效，只允许现有视频导入、转码和媒体替换所需的 `catalog` 管理动作。
- 微信调用始终有 OpenID，不能用服务票据绕过人员名单。`shop`、`ticketing` 不接受服务票据。

## 5. 邀请

管理员在人员页创建邀请，角色选「运营」或「管理员」，默认「运营」。邀请写入 `admin_invites`：

| 字段 | 含义 |
| --- | --- |
| `code` | 一次性随机码 |
| `role` | 领取后的角色 |
| `createdBy` | 创建者 OpenID |
| `expiresAt` | 创建后 24 小时 |
| `usedBy` | 领取者 OpenID；未使用为空 |

云函数用 `wxacode.get` 生成打开 `pages/admin/join/join?invite=` 加该码的小程序码。成功时页面可以把图片保存到相册。这种码打开的是已发布版本。未发布或生成失败时，邀请记录保留，页面提示「发布后才能生成小程序码」。不在小程序里手输邀请码，也不把码放进用户界面。

领取页只在带有效邀请码打开时绑定当前微信：

- 码不存在、过期或已使用：提示「邀请无效」，不改名单。
- 当前微信已是启用人员：提示「你已在名单中」，邀请不消耗。
- 当前微信已停用：提示「需要管理员重新启用」，不自动启用，邀请不消耗。
- 其余情况：写成邀请上的角色、启用，邀请记为已使用，进入工作台。

运营不能创建邀请。

## 6. 入口

「我的」每次显示时询问当前微信是不是启用人员。是，才在资料卡和版本之间显示「运营工作台」，右侧「进入」，样式仍用 `hub-item`。点进去直接打开工作台。不是，则这一行不渲染。

首页标题连点 8 次不再打开任何页面。

直接打开原来的口令页时：没有管理员就进入初始化页；已有管理员就回到「我的」，不显示口令输入。

工作台在管理员的日常三行下面增加「人员」。副文案是「管理员与运营」。运营看不到这一行。底部版本行不变。

人员页列出启用的管理员、启用的运营，然后是已停用的人。每行是昵称、角色和「启用」或「已停用」。管理员可以把别人设为管理员或运营，也可以停用、重新启用。对自己的行不提供这些操作。违反第 3 节时提示「至少保留一名管理员」或「不能修改自己」。

管理接口未授权时回到「我的」。运营误开人员页时留在工作台，并提示「只有管理员能修改人员」。

## 7. 不改什么

- 不改内容、商品、工单的业务规则。
- 不改顾客资料、客服通知和企业微信通知的收件规则。
- 不分内容、商品、工单的操作权限。
- 不在小程序里展示或修改 `ADMIN_PIN`。
- 不升版本号。

## 8. 测试

云函数测试覆盖：无管理员时口令绑定、已有管理员时口令不再绑定、启用人员可通过、停用后拒绝、运营调用人员接口得到 `FORBIDDEN`、不能修改自己、不能去掉最后一名管理员、邀请的领取、过期、重复使用和已停用微信。

小程序测试覆盖：「我的」只给启用人员显示入口，连点 8 次不再导航，运营的工作台没有「人员」，管理员可以进入人员页。

## 9. 验收

1. 普通用户的「我的」没有运营工作台。连点首页标题没有反应。打开旧口令页也进不了工作台。
2. 没有管理员时，用口令把当前微信设为管理员，之后口令不能再增加管理员。
3. 管理员生成的小程序码只能使用一次。对方领取后成为所选角色，并只在自己的「我的」看到工作台。
4. 运营能做内容、商品和工单，不能改人员。
5. 停用后，该微信立刻不能再调用管理接口，「我的」也不再显示入口。
6. 最后一名管理员不能被停用或降级。任何人不能修改自己的角色或启用状态。
