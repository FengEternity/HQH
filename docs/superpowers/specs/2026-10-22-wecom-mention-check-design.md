# 运营群按手机号发测试 @

日期：2026-10-22  
状态：已实现  
载体：微信小程序管理端 `pages/admin/inbox`、云函数 `ticketing`  
范围：绑定手机号后按这个号码在运营群发一条测试 @。页面展示已绑定的手机号，允许更换，发送失败写在卡片上。

## 1. 要解决什么

群机器人在 @ 不到人时仍返回成功。小程序以前只检查手机号是不是 11 位，开关显示「接收中」并不说明群里 @ 得到这个人。

企业微信的「手机号获取 userid」要先配置企业可信 IP，而可信 IP 又要求备案主体与本公司一致的域名。当前没有这样的域名，这条校验做不成。

绑定后发一条测试 @，由本人到群里确认。这一步能发现号码填错、人不在群里，以及用个人微信进群。

## 2. 决定

- 手机号绑定不调用企业微信通讯录接口。11 位号码写入 `mobile` 和 `wecomUserId`，`enabled` 为 true。
- 写入后用群机器人发一条测试文本。手机号放进 `mentioned_mobile_list`。正文包含「通知测试」，避免被当成新工单。
- 测试消息发送失败：绑定保留，卡片显示「已绑定，但测试消息没发到群」并带错误码。未配置 `WECOM_GROUP_WEBHOOK` 同样算测试发送失败。
- 正式通知 @ 所有 `enabled` 且 `wecomUserId` 非空的人。手机号走 `mentioned_mobile_list`，成员 ID 走 `mentioned_list`。
- 测试消息发出，只说明消息进了群。页面不把它写成「已经可以 @ 到你」。
- 关闭开关只把 `enabled` 设为 false，保留手机号，不发测试。每次从关闭改为开启，都按已存的手机号或成员 ID 再发一条测试。更换手机号同样发测试。
- 用登录码绑定的路径保持不变，不发测试消息。

## 3. 页面

客服工单页只留一行「接收会话通知」，右侧是当前状态和「设置」。点这一行进入 `pages/admin/notify/notify`。手机号、开关和说明都在这一页。

固定说明两句：

1. 开启后，用户发来消息会在运营群 @ 你。手机号要和企业微信通讯录里的一致。停止后不再 @ 你。
2. 群机器人无法确认 @ 是否生效。收不到时，请确认你是用企业微信加入该群。

`csNotifyConfig` 增加 `mobile`。已绑定且没有单独的 `mobile` 时，若 `wecomUserId` 是 11 位手机号，就用它来显示。

- 未绑定：手机号输入框和开关。打开开关时绑定并发测试。
- 已绑定：展示完整手机号、开关，以及「更换手机号」。更换后再次发测试。
- 当次测试已发出：卡片留下「测试消息已发到运营群，请现在去看有没有 @ 到你。没有的话，请确认你是用企业微信加入该群。」离开再进入后这句消失。
- 测试未发出：绑定状态保留，错误写在卡片上。

右侧标签仍是未绑定、未开启、接收中。

## 4. 失败文案

群机器人发送失败时，卡片显示「已绑定，但测试消息没发到群」，并带错误码或「未配置运营群机器人」。

## 5. 数据

`admin_notify_subscribers` 增加 `mobile`。手机号绑定把同一个号码写入 `mobile` 和 `wecomUserId`。

## 6. 不改什么

- 不调用「手机号获取 userid」。
- 不要求企业可信 IP 或本公司域名。
- 正式通知正文是四行：`新消息`、昵称、触发这次通知的那句用户原话、发送时间。没填昵称时写「未留昵称」。原话去掉首尾空白，换行压成空格，超过 80 字保留前 80 字并加上「…」。不放微信号、手机号、OpenID，也不放系统提示。测试消息正文不变。
- 不把企业 ID、应用 Secret、群机器人地址写入仓库。
- 不恢复微信订阅消息。
- 个人应用通知仍保持跳过。
