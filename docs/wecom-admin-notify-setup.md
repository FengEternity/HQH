# 客服工单企业微信持续通知

这份文档交给企业微信管理员和运营。Secret、群机器人地址只放在云函数环境里，不要发到群里，也不要写进仓库。

小程序 AppID：`wxfbc102f9a77567b3`。

## 1. 企业微信管理员（做一次）

### 1.1 记下企业 ID

1. 打开 [企业微信管理后台](https://work.weixin.qq.com/wework_admin/frame)，用有应用管理权限的管理员登录。
2. 进入「我的企业」→「企业信息」。
3. 复制企业 ID。这是 `WECOM_CORP_ID`。

### 1.2 关联小程序

1. 进入「应用管理」→「应用」。
2. 在自建应用里找已经关联小程序 `wxfbc102f9a77567b3` 的应用。
3. 没有就创建应用，或把这个小程序关联上去。授权时会跳到微信公众平台，用该小程序的管理员微信扫码。
4. 进入该应用，复制：
   - AgentId，即 `WECOM_AGENT_ID`
   - Secret，即 `WECOM_AGENT_SECRET`
5. 把要收通知的运营加进这个应用的可见范围。不在范围内的人绑定会失败，也收不到个人通知。

### 1.3 运营群机器人

1. 打开要收通知的企业微信群。
2. 群右上角「…」→「添加群机器人」→ 新建。
3. 复制 Webhook 地址。这是 `WECOM_GROUP_WEBHOOK`。留空则只发个人通知，群不再补发。

## 2. 发布（做一次）

用本地 `main` 的最新代码。云端旧版本没有这次改动。

### 2.1 云函数环境变量

在微信云开发里打开云函数 `ticketing` 的环境变量，填入：

| 变量 | 内容 |
| --- | --- |
| `WECOM_CORP_ID` | 企业 ID |
| `WECOM_AGENT_ID` | 应用 AgentId |
| `WECOM_AGENT_SECRET` | 应用 Secret |
| `WECOM_MINI_APPID` | `wxfbc102f9a77567b3` |
| `WECOM_GROUP_WEBHOOK` | 群机器人 Webhook |
| `WECOM_CALLBACK_TOKEN` | 接收消息服务器的 Token，与企业微信里填的相同 |
| `WECOM_CALLBACK_AES_KEY` | 接收消息服务器的 EncodingAESKey，43 位，与企业微信里填的相同 |

已有的 `ADMIN_PIN`、`CS_REPLIED_TPL` 等变量保持不动。

企业微信要求先配好「接收消息服务器 URL」，才允许填写企业可信 IP。云函数上传后，在云开发的 HTTP 访问服务里把路径 `/wecom` 指到 `ticketing`，把控制台给出的 https 地址填进「工单助手」的接收消息服务器。Token 和 EncodingAESKey 两边必须一致。保存通过后，再把云函数报错里的 `from ip` 填进企业可信 IP。

### 2.2 上传

1. 微信开发者工具中，右键 `cloudfunctions/ticketing`，选择「上传并部署：云端安装依赖」。
2. 再上传小程序体验版或正式版。运营必须打开包含这次改动的版本，旧包仍是一次性订阅。

## 3. 每位运营（各做一次）

每个人用自己的微信打开小程序。绑的是这个微信号，换一个人就要再做一遍。

1. 打开体验版或新正式版。首页标题连点 8 次，输入运营口令，进入后台。
2. 打开客服工单，找到「接收新工单通知」。
3. 填写自己在企业微信通讯录里的 11 位手机号。
4. 打开「接收通知」。成功后提示「已开启」，状态为「接收中」。
5. 这个人要在收通知的运营群里。群机器人会按这个手机号 @ 他。

关闭开关后，新工单不再 @ 这个手机号。所有人都关闭时，群里不会发这条消息。

## 4. 通知和会话

用户在客服页发出的每一条消息都会进入当前会话，包括「领取账号」和「怎么找视频」。这些内容不再自动回答。打开客服页时仍有一句欢迎语。

- 群机器人发一条「新消息」，只 @ 状态为「接收中」的手机号。
- 运营刚回复后的 10 分钟内，用户接着说不再 @。超过 10 分钟用户再发，会再 @。
- 没配群机器人时，这一次不发。配好之后，下一条该通知的用户消息会补发。
- 能进后台的人看到未读就可以回复。谁先发出回复，这段会话就由他持有 10 分钟。
- 持有期间别人不能回复。持有人可以点「放开」。10 分钟没有新的回复，持有自动结束，别人可以回复。
- 列表按最后一条消息排序。最后一条是用户发的，标成未读。
