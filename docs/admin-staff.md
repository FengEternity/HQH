# 运营人员使用说明

这份文档给管理员和运营。口令只放在云函数环境变量 `ADMIN_PIN` 里，不要发到群里，也不要写进仓库。

管理员和运营都能做内容、商品和客服工单。管理员额外可以邀请人员、改别人的角色，以及停用或重新启用别人。

## 1. 上线前做一次

1. 上传并部署云函数 `catalog`、`shop`、`ticketing`。三个函数继续配置同一个 `ADMIN_PIN`。
2. 打开小程序，或在云函数测试里对 `catalog` 传入 `{ "action": "initDb" }`。这会补上人员相关的数据表。
3. 在云开发控制台把新建集合的权限设为仅管理端可读写。

没有微信身份的视频导入和转码脚本，仍用这个口令向 `catalog` 换取服务票据。商品和工单接口不接受这张票据。

## 2. 绑定第一个管理员

还没有管理员时，用开发者工具把启动页设为 `pages/admin/login/login`，或直接打开这个页面。输入口令后，当前微信成为管理员，并进入工作台。

已经有管理员之后，再打开这个页面不会出现口令框，也不会再增加管理员。

## 3. 邀请其他人

1. 管理员打开小程序，进入「我的」→「运营工作台」→「人员」。
2. 点「创建邀请」，选择「运营」或「管理员」。
3. 允许保存到相册。图片在二维码下面写着截止时间和「24 小时有效」。把这张图单独发给对方。
4. 对方用自己的微信扫码。领取成功后进入工作台，并在自己的「我的」里看到「运营工作台」。

邀请从创建起 24 小时内有效，只能使用一次。超过图片上的截止时间再扫，会提示「邀请无效」。小程序码打开的是已发布的正式版。正式版里还没有领取页时，扫码会显示「页面不存在」；等该版本发布后，同一张未过期的码可以继续用。还没发布、或生成失败时，页面提示「发布后才能生成小程序码」。

对方已经是启用人员时，扫码会提示「你已在名单中」。已经停用的人扫码会提示「需要管理员重新启用」，邀请不会把他自动加回来。

## 4. 日常进入

启用中的管理员和运营，打开「我的」就能看到「运营工作台」。普通用户和已停用的人看不到这一行。

正式版发布前，首页标题连点 8 次会打开运营登录页，不检查是否已在名单中。正式版发布后删除这个手势。

## 5. 调整人员

人员页按启用的管理员、启用的运营、已停用的人排列。没有设置昵称时显示「未设置昵称」。

点别人那一行的「管理」：

- 「设为管理员」或「设为运营」立即改角色。
- 「停用」需要再确认一次。停用后，对方不能再进工作台，下一次管理请求也会被拒绝。
- 「启用」恢复原来的角色。

自己那一行没有「管理」。不能把启用中的管理员减到没有。页面会提示「不能修改自己」或「至少保留一名管理员」。

运营打开「人员」时会提示「只有管理员能修改人员」，并回到工作台。

## 6. 人员离开时

停用他的微信即可，不必更换共用口令，也不影响其他人员。对方的「我的」里不再出现运营工作台。

如果停用的是唯一还能进工作台的管理员，系统会拒绝这次操作。先把另一名启用人员设为管理员，再停用离开的人。
