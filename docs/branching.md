# 分支与发布

## 两条长期分支

| 分支 | 用途 |
| --- | --- |
| `main` | 发布与验证。只放准备上传体验版/正式版、或已经过验证的代码。开发者不在这条分支上做功能、修 bug、改文档。 |
| `dev` | 研发、联调、测试。新功能、重构、产品文档与实现计划的日常提交都在这里。 |

## 工作方式

1. 开始干活前：`git checkout dev`（没有本地 `dev` 时从已发布的 `main` 拉：`git checkout -b dev origin/main`）。
2. 功能可以再从 `dev` 拉短生命周期分支（例如 `feat/shop-cart`），做完合并回 `dev`，不要直接合并进 `main`。
3. `dev` 上自测通过、准备发体验版或正式版时，再把 `dev` 合入 `main`（PR 或快进），在 `main` 上用微信开发者工具上传、提交审核。
4. 发布后若要继续开发，切回 `dev`，不要停在 `main` 上改。

## 禁止

- 在 `main` 上直接 `commit` 功能代码（热修发布也先在 `dev` 或 hotfix 分支改，验证后再进 `main`）。
- 把未验证的云函数、支付、密钥相关改动推到 `main` 当日常备份。
- Force push `main`。

微信侧：开发者工具导入仓库后，上传体验版应对准 `main` 的已验证提交；日常预览可用 `dev` 本地编译，不要把 `dev` 未验收提交当成「已发布」。
